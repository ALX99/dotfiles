# Repository Map

## Repository Purpose

This Stow-managed personal repository holds shell tooling, desktop applications, system setup, and AI-agent configuration. `.local/`, `home/`, and `.config/` are packages installed into `~/.local`, `~`, and `~/.config`; `.stowrc` deliberately disables Stow folding.

## Architecture and Ownership

- `.local/bin/` owns user executables. `home/` owns configuration, including Bash, SSH, Git, and agent files. Start shell changes at `home/.profile`, `home/.bashrc`, and `home/.bashrc.d/`.
- `.config/` owns application configuration. Neovim starts at `.config/nvim/init.lua`; compositor, terminal, and other desktop settings live beside it. Karabiner's JSON is generated from `misc/karabiner/karabiner.cue` into the tracked `misc/karabiner/karabiner.json`, and `mise run install` copies it to `~/.config/karabiner/karabiner.json` when that path is absent; Karabiner rewrites the installed file itself, so it is copied once rather than stowed as a link its writes would dirty. Herdr plugins share CLI execution and validated workspace fields through `.config/herdr/plugins/_shared/herdrlib.py`; each plugin owns its Git or installation policy.
- `misc/` owns Arch, systemd, pacman-hook, and keyboard assets. `.devcontainer/` defines the Arch development environment rather than the installed host configuration.
- `home/.agents/skills/` contains harness-independent skills. Pi-specific settings, prompts, themes, and skills belong in `home/.pi/agent/`; do not put Pi-only material in the shared skill tree. `home/.pi/agent/settings.json` owns local Pi defaults and external package registrations.
- `home/.pi/agent/extensions/` is a strict TypeScript/NodeNext package. The `zooid/` package exposes one `index.ts` entry point that registers its feature modules in order, while the other feature directories expose `*/index.ts` entry points; `_shared/` supplies common support and `**/tests/` owns coverage. Effect is the extension idiom: it owns I/O, concurrency, lifetimes, and error channels, while pure parsing, validation, state transitions, and rendering stay synchronous. `_shared/fs.ts` is the only module allowed to import `node:fs` and exports Effect-returning functions directly instead of a service layer, since the package has one implementation, `_shared/effect-runtime.ts` holds the only promise bridges (`runPromise`, `runFork`), and `_shared/errors.ts` holds the shared `FsError` tagged error and the caught-value narrowing helpers (`toError`, `hasNodeErrorCode`), while tools that fail in their own channel carry their own tagged errors. Extensions keep their dispatch in session-entry-derived state and pass through the bridges at Pi's promise boundaries. `zooid/process-reaper.ts` owns session-scoped Bash process-group markers and cleanup for agent-started background descendants. `tasks/` owns task queues (one to 100 tasks, including discovery tasks that add follow-ups) with per-task checkpoints and chained branch-summary compaction of completed task traces: `state.ts` owns the queue model, session-log replay, and transitions without Pi APIs, `index.ts` owns the Pi integration, events, commands, checkpoint navigation, and status text, `tools.ts` the model-facing schemas, and `dashboard.ts` the read-only UI. `skills/` owns `/skills` discovery, validation, token accounting, and the pre-first-turn model-visibility overlay while preserving Pi's native `/skill:name` expansion. `ask-question/` and `codex-apply-patch/` own their corresponding tools. `codex-web-search/` owns hosted `web_search` injection for OpenAI Responses providers, its `~/.pi/codex-web-search.json` config, and the `provider_stream_event` subscription that feeds the search transcript entry on every transport. Those entries are TUI-only, and a search reaches the model only through the server-side response chain Pi continues across requests, so `recall.ts` decides which recorded searches the model can still reach: a compaction rewrites the input that chain hangs off, and any other change to the request body makes Pi start a new chain. `index.ts` marks the branch's earlier records unreachable at each prompt, exposes `web_search_log` only while such records exist, and injects a manifest of their queries and source hosts — never the URLs, which stay in the record — naming the tool or, when the session's selection excludes it, the session file. `zooid/copy-code.ts` owns code-block clipboard selection; `zooid/nested-context.ts` loads subtree instruction files as tools touch files below the session working directory. `zooid/caffeinate.ts`, `zooid/statusbar.ts`, `zooid/model-shortcuts.ts`, `zooid/interrupt-on-empty-enter.ts`, `zooid/retry.ts`, `zooid/schedule.ts`, and `zooid/title.ts` own small host-integration features; `zooid/compact.ts` replaces the builtin bash, edit, and read tool rows with compact change renderings; `zooid/systemprompt.ts` owns the replacement system prompt and its `/systemprompt` viewer, rebuilding the prompt from the live tool registry so the advertised tools and their guidelines never drift from the enabled set, and listing the tools `codemode` moved behind its own tool separately from the ones the model calls itself.

## Key Flows and Sources of Truth

`mise run install` restows the three user packages and links shared skills; it can change `$HOME` and enable the user `ssh-agent`. `mise.toml` owns the bootstrap manifest and tools; `.mise/tasks/` owns automation as standalone scripts (entry points flat, subsystem work namespaced like `pi:check` and `karabiner:check`, generators inverted as `gen:<area>` and run together by `mise run gen`). Together they are the source for installation and host setup. GitHub Actions installs the tools from `mise.toml` and runs `mise run check` for every push and pull request.

Within Pi extensions, prompt-owning extensions run in chain order and the last writer wins; the live tool selection is Pi's own, narrowed only by the session's `--tools`/`--exclude-tools` flags and by what `codex-apply-patch`, `tasks/`, and FFF activate. `systemprompt.ts` reads that selection when it rebuilds the prompt. `skills/index.ts` reconciles live and restored skill visibility through one name-to-selection map; native session entries remain the durable source for branch-local selections, and its `enabledModelSkillNames` accessor lets a replacement prompt honor them without sharing state. `zooid/process-reaper.ts` owns a process-local group registry; its temporary marker files only hand PIDs from Bash to that registry and are not durable session state.

The tasks extension's model-facing protocol is intentionally limited to `create_tasks` with plain task titles and `finish_task` with a status, outcome, and optional `addTasks` placements. After checkpoint compaction, hidden `tasks:continue` custom messages trigger model continuation with the next task title (or request a final summary); a hidden `tasks:reminder` custom message asks for the current task's outcome when the agent settles with it still pending, at most once per task, and never in headless mode, while deferred user input is being replayed, or after a turn the user interrupted or that failed; user-facing active-task status shows progress separately, while stable IDs remain in tool results and checkpoint data. In TUI mode, `/tasks` opens a read-only dashboard with queue/task navigation and scrollable recorded outcomes, changed files, and discovered tasks; `/tasks status` keeps the concise notification. Dashboard history and execution share the same validated branch-entry replay, including completed queues, without adding model tools or separate persistence. Existing tasks are monotonic from the model's perspective: additions are atomic with outcomes, while IDs are generated by the plugin and exposed only as stable queue references; additions may target the current task, the queue end, or an existing pending task, while file attribution, checkpoint lifecycle, replay, and human cancellation remain plugin bookkeeping, with no model-facing task history or destructive queue mutation tool.

Nested context restores on branch navigation and uses native steering so instructions reach the next model step.

## Where to Start

- For user commands or shell behavior, inspect `.local/bin/` and the `home/` shell file.
- For an application or desktop change, begin under `.config/`; follow related Colemak-DH mappings across affected applications.
- For Karabiner changes, edit `misc/karabiner/karabiner.cue`, then run `mise run gen:karabiner` and `mise run karabiner:check`; copy `misc/karabiner/karabiner.json` over `~/.config/karabiner/karabiner.json` to apply a regenerated config to an existing install.
- For Twilight Bloom changes, edit `misc/themes/twilight-bloom.cue`, then run `mise run gen:theme` and `mise run theme:check`. It generates Ghostty, Herdr, and Pi themes.
- For system provisioning or keymaps, begin at `misc/` and `mise.linux.toml`. Do not casually run `MISE_ENV=linux mise bootstrap` or the `linux-system` task; they make privileged host changes.
- For Pi behavior, begin at the relevant extension entry point and its tests. Run `mise run pi:check` for extension changes; use `bash -n home/.bashrc home/.profile` for shell changes.

## Critical Constraints

Keep tracked links as links: `CLAUDE.md` targets this file, `home/.bash_profile` targets `.profile`, and the Claude/Codex instruction links lead to `home/.pi/agent/APPEND_SYSTEM.md`. Extensions require Node 26+, pnpm, tabs, and `oxfmt`; the Pi packages follow the host Pi release line through caret ranges, while `effect` is pinned to the 4.0 release-candidate line its guide targets. `mise run pi:deps` installs the dependency set into both the repository tree and `$HOME/.pi/agent/extensions`, because Pi resolves extension imports through jiti from that installed directory. `home/.pi/agent/settings.json` enables the built-in `codemode` tool with `codemode.mode: "only"`, so every active `direct` tool reaches the model only through a `codemode` script. Validation and domain modeling use Effect `Schema`. Errors that type an Effect or `Result` channel are `Schema.TaggedError` classes carrying a `message` field, because `runPromise` rejects with the error itself; failures whose message is the entire contract, such as tool argument and input validation, stay plain `Error`s thrown at that boundary. Do not reintroduce `zod` or `neverthrow`: pure parsers return Effect `Result`, and only Pi tool parameter schemas use `typebox`. Keep the package manifest, lockfile, workspace policy, and `codex-apply-patch` grammar synchronized when upgrading those packages. That extension vendors Codex's `apply_patch` Lark grammar, keeps a test that checks it against the installed `codex` binary, and replaces Pi's edit/write tools for models whose `compat.supportsOpenAIGrammarTools` flag makes the provider emit OpenAI custom grammar tools. Colemak-DH navigation is coordinated across Nvim, tmux, Sail, keyd, Karabiner, Ghostty, and readline. `misc/themes/twilight-bloom.cue` is the source of truth for the Ghostty, Herdr, and Pi light/dark themes; the generator preserves Ghostty's ANSI palette and explicitly maps UI-only surfaces for Herdr and Pi. Bash PS1 and LS_COLORS consume the Ghostty ANSI palette directly. Pi picks the generated pair through its `light/dark` theme setting, and `pi --export` renders before theme setup so it stays on the built-in theme. GNU tools come first in PATH on macOS through `home/.profile`, so non-interactive shells and coding agents get GNU cat, sed, find, grep, and tar; call those plain names in scripts instead of g-prefixed ones or BSD fallbacks, and keep g-prefixed aliases out of `home/.aliasrc`.

## Maintenance

Keep this repository map current. When a change adds, removes, or relocates a major subsystem; changes an architectural boundary or source of truth; or introduces a critical repository-wide constraint, update `AGENTS.md` in the same commit. Do not record routine implementation details or file-level churn.

# Learning More About Effect

The Pi extensions use the Effect TypeScript library.

Before writing any Effect code, first read `home/.pi/agent/extensions/node_modules/effect/AGENTS.md` **completely**, and follow the links in the file when required.

If you need to learn more about particular Effect apis and concepts that the guide doesn't cover, search through the source code in `home/.pi/agent/extensions/node_modules/effect/src`.
